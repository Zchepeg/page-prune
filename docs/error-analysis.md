# 共同漏检与输入信息诊断

固定153条开发验证样本中有25条人工广告，21条DOM文本为空。比较50%与100%证据丢弃模型，温度均为1、输入均清空规则证据，两组共同漏判13条广告，来自5个域名。13条全部文本为空，其中9条资源URL为空；没有发生输入截断。规则层对其中6条走阻断、7条走灰区，因此纯模型漏检不能直接视为扩展漏拦。

更正：文本和资源为空不等于页面空广告位。13条截图均有视觉变化，人工查看示例能看到iframe或图片渲染的内容，但这些视觉文字未进入模型状态。当前模型是文本/结构决策器，没有图像编码输入，这构成明确的观测缺口。跨源iframe内容、图片文字与外层DOM短文本不能等同。

另一个示例eval-f60697bc279d78aff2b0标注为广告，类名含google-ad，但截图看起来是安全新闻文章卡片。它可能存在容器截图与标签范围不一致，或标签需要复核；当前不自动修改人工标签，不以机器判断宣称人工标注错误。样本仍在原开发集，应记录疑点后由人工确认。

结构检查发现浏览器候选已经含direct_resource_urls及resource_ownership_known，检测器也区分自身与后代资源，但candidate-features-v2状态没有这些字段，训练重建也可能丢失归属。这解释了为什么仅去掉规则证据会同时拿走有价值的资源归属线索，不能将其视为纯粹去除捷径。

本轮新增显式选择的candidate-features-v3状态，保留自身资源URL及归属已知标记，并使数据标准化往返保留它们。默认状态仍为v2，旧检查点、正式部署和已有评测保持原输入；没有用新版状态直接喂旧模型。历史数据若没有原始归属信息，不能猜测补全。

新版状态只是实验准备，尚未证明提升召回。后续顺序：先人工复核疑似标签/容器范围问题；再从有原始候选的数据重建版本化输入，保持域名隔离训练校准；视觉证据缺失单独列为证据不足或待复核，评估受预算约束的可选视觉辅助。无需立即将整页截图、完整HTML或未知iframe代码送入模型。

本次不改原标签、不改变阈值、不训练或部署新检查点。原始截图与逐样本预测继续保存在runs目录中。

## 重建与训练可行性核查

原始旧人工基准483条全部未保存资源归属；新补充308条全部保存。已通过scripts/rebuild_ownership_state.py分别重建human-development-v3及calibration-supplement-v3独立快照，保留每条ID、标签、域名、切分、任务说明与既有规则证据；旧数据明确归属未知，不猜测恢复。

这意味着当前294条训练数据没有真实已知归属监督，直接训练v3无法有效检验新字段价值；155条新校准及153条新验证继续保留原用途，不转作训练。下一步需要来自训练用途域名、真实保留归属信息的新人工标签，或先设计独立的新实验切分并放弃相应数据旧角色，不能继续引用其旧评测身份。

单条疑似范围问题通过scripts/prepare_label_scope_review.py准备于runs/label-scope-review-v1，单独人工复核，不覆盖原标注。即使确认更正，旧报告仍作为当时标签版本的历史结果保留，后续需新版本数据及报告。

六项相关测试验证新版状态往返、直接/后代资源区分、默认v2兼容及重建不改变监督标签。正式部署与模型权重未改。

## 单条人工复核结论

eval-f60697bc279d78aff2b0已由用户再次独立确认标签为ad，与原标签一致。保留原标签，不生成更正版本；此前“截图看起来是新闻卡片”只作为机器提出的复核疑点，不能当作标注错误证据。本例仍计入模型漏检，提示候选外观与广告语义可能不一致，后续应补充可核验的上下文或资源证据。
