# v2/v3配对训练结果

两组均使用326条人工训练、37域名，原99条早停验证、两轮训练、种子42和50%证据丢弃率，其余参数一致。新增32条中只有5条广告且来自4域名，资源归属监督有限。数据配对保持ID、标签、域名、任务说明和证据一致，只改变输入版本和资源归属字段；不同token序列仍可能引起训练轨迹变化。

检查点现在记录state_schema。训练拒绝混合版本，校准与检查点评估校验版本，广告任务运行时对有版本元数据的检查点拒绝错版输入；无该字段的历史检查点保留兼容。探针问题不套用候选状态校验。

两组分别在相同155条人工校准上拟合温度：v2为0.3122、v3为0.4892。固定开发验证153条、10域名，包含25条广告与128条非广告。

温度1时，无证据分类计数仍为v2的15/25与v3的24/25，表明这部分排序变化不是温度缩放产生。有证据时，v3温度1策略处理23条广告且无动作误杀；校准后升为25条，同时新增1次动作误杀。两版两种输入各截断3条，新增字段未在此批增加截断条数。

无证据分类召回差异为+36个百分点，配对域名2000次百分位区间约[+8.7,+72.7]；有证据分类差异+4个百分点，区间[0,+13.3]。区间仅描述小型复用开发集上的域名抽样，不包含训练随机性，不能用作新独立测试的成功声明。

本次提供了资源归属表示值得继续验证的开发证据，但不能将差异严格归因于某一字段：schema标识、token位置、序列长度与优化轨迹同时变化。进一步需在同一v3检查点上清空/打乱归属字段进行输入消融，并检查其依赖是否符合预期；最终冻结候选后使用新独立盲测及页面兼容验证。不能在当前成绩上挑选无证据分支后再称其为独立验收。

有证据分支存在新增误杀，当前不部署任何配对候选、不改阈值。默认服务继续使用v2输入；v3运行时接入仍需携带原始Candidate归属字段，不能仅修改检查点路径。

全项目165项测试通过。运行入口scripts/run_ownership_ablation.py，汇总入口scripts/summarize_ownership_ablation.py；模型位于runs/ownership-paired-v2-v1、runs/ownership-paired-v3-v1；逐样本结果与聚合报告位于runs/ownership-paired-experiment-v1，保持本地。

后续输入消融已完成，见ownership-input-ablation.md：清空或移除资源归属后大部分收益仍保留。因此本报告的版本差异不能解释为“模型已经学会资源归属”，其机制尚未确定。
