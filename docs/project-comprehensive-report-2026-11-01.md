# PagePrune（滤页）项目综合技术报告

报告日期：2026年11月1日  
项目作者：Zchepeg  
当前扩展版本：0.10.1  
报告范围：当前工作区代码、配置、已保存的评测与实验记录；不代表已发布版本。

## 1. 项目概况与当前结论

PagePrune（滤页）是面向 Chromium 浏览器的本地广告拦截研究项目。它结合静态网络规则、页面元素检测、本地分类器和执行策略，重点评估模型能补上多少规则漏检，以及会不会误伤正常内容。

项目不依赖官方 Jev 实现。“JEV”在本项目中主要指类型化决策与执行协议，而不是另一个独立基础模型。模型主干采用 Qwen3-4B-Base，配合 LoRA 和选项指针分类头训练。

目前工程链路已经完整：扩展执行、候选采集、安全通信、人工复核、离线训练、概率校准、评测和运行监测均有实现。历史部署检查点的独立评测未证明额外广告召回收益；新完成的352条冻结人工盲测则支持轻量与Qwen候选级联具有额外动作召回，但Qwen增加了误杀与计算成本，v3优势仍未跨种子稳定复现。候选尚未替换当前部署。首轮人工训练曾仅改善分类而没有动作收益，后续校准候选和新盲测另列，不能将不同阶段合并为一次成功实验。

当前适合以“可运行、可审计的广告屏蔽研究原型”公开源码，不适合宣传为已经验证高准确率的通用广告屏蔽产品。

## 2. 需求与设计原则

项目围绕四项约束设计：

1. **把模型成本集中在灰区。** 明确的域名事实与规则证据优先处理，避免逐元素调用大模型。
2. **分类与页面动作分离。** 广告概率不能直接等同于阻断权限，必须经过风险策略。
3. **数据来源可追溯。** 人工标签、规则弱标签、合成样本和模型推断分别记录，不能相互冒充。
4. **异常时保留页面可用性。** 本地服务不可用、模型加载中或预算耗尽时，模型路径放行或等待复查，浏览器静态规则继续工作。

浏览器扩展可以在没有本地模型的情况下执行已有静态网络规则、元素隐藏和相关浏览器防护；灰区模型判断与本地复核服务需要用户启动服务。公开默认配置使用启发式后端以便验证安装，不包含可直接下载运行的训练权重。

## 3. 系统总体结构

```text
浏览器扩展
  ├─ 静态网络规则与页面元素隐藏
  ├─ 有界候选发现、人工点选标记
  └─ 低比例 SSA 结构观察
            │ 配对后的加密本地通信
            ▼
输入契约校验与隐私脱敏
            ▼
确定性检测、候选排序与决策缓存
  ├─ 明确候选 → 规则快速路径
  └─ 灰区候选 → 去重、预算控制 → Qwen 类型化决策
                                     ▼
                          独立风险策略与不确定性处理
                                     ▼
                          隐藏 / 阻断 / 放行 / 复核
                                     │
                     审计、人工复核及离线训练数据
                                     ▼
                      训练 → 校准 → 评测 → 人工部署
```

### 3.2 技术栈

浏览器侧使用 JavaScript、HTML、CSS、Manifest V3、declarativeNetRequest、内容脚本和 MutationObserver。本地服务主要使用 Python 标准库 HTTP 服务，安全模块使用 cryptography。模型侧使用 PyTorch、Transformers、PEFT、Accelerate、bitsandbytes 和 safetensors。实验轻量模型使用 scikit-learn；测试使用 pytest，浏览器自动化工具包含 Playwright。

## 4. 广告检测与决策算法

### 4.1 浏览器与确定性检测

静态网络规则覆盖广告网络、分析脚本、社交像素与会话录制等请求。域名列表通过分块 `requestDomains` 组织，减少逐域名规则膨胀。大规模 DNS 来源规则限制第三方请求，避免直接阻断主文档导航。

页面层结合 CSS 隐藏、动态 DOM 检查、元素尺寸、位置、可见性、资源 URL 和广告标记发现候选。候选受单页数量、字段长度和请求预算限制，不将完整页面交给模型。检测器区分元素自身与后代资源，降低包含广告子节点的正常容器被整体误判的风险。

### 4.2 Qwen 选项指针分类

模型输入由任务说明、脱敏候选状态与类别选项组成。Qwen 提取状态与选项表示，pointer head 对候选选项计算分数，再经温度缩放转换为概率。它直接完成有限选项评分，不需要生成长文本回答。

选项隔离注意力限制各选项读取公共状态和自身内容，决策位置读取全部选项；训练随机打乱选项顺序，以减少位置捷径。新训练采用广告与非广告二分类，“证据不足”由低置信度、概率间隔、截断等协议条件产生，不作为普通内容类别强行学习。

训练任务说明与状态序列化已建立共用入口；新检查点保存任务说明和相关元数据，防止训练、校准和部署各用不同输入。旧检查点保持历史兼容，不在修改输入后沿用旧效果声明。

### 4.3 规则—模型级联与风险策略

规则快速处理明确候选，灰区交给模型。协议支持边界挑战和规则—模型分歧记录；分歧不直接触发更强阻断，而是降低确定性并进入复核。当前没有以实验候选替换默认模型，也未因开发成绩开放更激进动作。

模型输出继续经过策略检查：广告概率、决策档位、受保护标签、结构风险以及动作可恢复性。正文、导航、表单、输入框等高风险元素受到额外保护。分类误判与页面动作误杀分别统计，因为错误分类不一定最终破坏页面。

### 4.4 主动学习与 SSA 影子审计

主动学习根据规则—模型分歧、不确定度和规则边界安排复核优先级，并保留普通元素对照采样。模型预测不会直接变成人工标签；规则采集保留弱标签身份。

SSA（Shadow Audit，影子审计）观察已经放行但仍可疑的元素。检测分数在 0.45–0.90 的合格候选按 0.1%、0.5%、1% 分层采样，每标签页每小时最多 3 个、每域名每小时最多 20 个。探针在有限等待后检查结构变化、可见性和已有资源关联，不额外访问广告地址、不点击广告、不伪造曝光，也不执行未知代码。

探针类型与延迟由摘要确定，保证预算受控和窗口内可复现。探针只提交严格白名单结构统计；高信息结果进入复核，不自动改变页面或加入训练。历史离线评测若没有实际探针记录，应标为未执行相关分析，不能把发现数为零解释为探针已验证无效。

### 5.2 训练与部署约束

训练采用 LoRA、域名隔离切分、早停、最佳验证检查点恢复及独立校准切分。开发策略包括规则证据随机丢弃、表面特征丢弃、域名频次加权和标签平滑，以减轻规则捷径与高频网站记忆。

数据来源、输入版本、任务说明、随机种子、数据哈希与检查点信息用于追溯。候选训练完成后不自动提升为正式模型；本机当前自动训练关闭，训练与在线决策分离。仓库保留相关调度能力，不代表默认服务会自行训练。

## 6. 模型失效诊断与近期实验

### 6.1 历史纯模型零召回的解释

诊断发现三类信号：训练任务说明与部署说明不一致；训练加载器可能补充规则证据，而纯模型评测清空规则证据；历史校准数据以构造样本为主。它们构成输入与分布漂移风险，但尚不能证明已经完全解释独立测试的零召回。

在正式序列化统一后的开发对照中，新人工模型能改善分类，却可能因概率未达到隐藏阈值而没有页面动作收益。温度缩放能改变置信度与拒绝比例，不能改变二分类 argmax 排序，因此不能单独修复语义排序错误。

另一个观测缺口是视觉内容：部分人工广告外层 DOM 文本和资源线索为空，但截图中存在 iframe 或图片广告。当前模型没有视觉编码，不能从未进入状态的图像文字作判断。后续需要区分证据缺失与模型理解失败，而不是持续增大同一种文本模型。

### 6.2 资源归属输入实验

实验性 `candidate-features-v3` 显式保留自身资源 URL 和归属已知标记；默认输入仍是 v2。历史记录缺少归属信息时保留未知，不猜测恢复。

v3 单次结果曾优于 v2，但换随机种子后优势反转；恒定归属字段控制组也复现相近高分。因此，目前没有证据证明真实归属字段带来稳定收益。实验版本保留用于审计，不作为默认架构升级。

无规则证据、各自校准后的同集开发结果如下。这里“不稳定”特指v3相对v2的输入效应与策略收益，不能笼统解释为所有输入下分类都不稳定。

### 6.3 CPU 轻量基线

已建立字符 TF-IDF 与逻辑回归对照。在固定开发验证集、有规则证据并完成各自校准时，轻量模型识别广告 18/25，Qwen v2 两个种子分别为 24/25、25/25；轻量策略处理 13/25，并出现 1/128 动作误杀，尚不足以替换服务。

轻量模型拟合约 272 ms，压缩文件约 240 KiB；文件大小不是运行内存。相同前 20 条状态、预热后串行后端测试中，CPU 轻量模型 P95 为 0.606 ms，NF4 Qwen 为 91.752 ms。该结果不含 HTTP、浏览器、批处理与完整页面动作，不能作为整页提速倍数。

| 成本与收益（有规则证据） | CPU轻量 | Qwen v2种子42 | Qwen v2种子7 |
| --- | ---: | ---: | ---: |
| 分类广告召回 | 18/25 | 24/25 | 25/25 |
| 策略处理广告 | 13/25 | 20/25 | 23/25 |
| 动作误杀 | 1/128 | 0/128 | 0/128 |
| 后端P95 | 0.606 ms | 本次未测 | 91.752 ms |
| GPU显存 | 不需要 | 本次未测 | 已分配约2620 MiB、保留约4084 MiB |
| 压缩模型文件大小 | 246232字节 | 本表未测 | 本表未测 |

轻量文件大小不能与Qwen显存预算直接比较。Qwen在该开发集取得更多策略广告动作，但需要显著更高的推理成本；有限样本零误杀不表示真实风险为零，尚不能仅据此断言4B模型值得部署。

轻量高置信放行预筛选也已离线核查：严格门槛没有可节省调用的样本，稍宽门槛开始漏放广告，因此未启用。

## 7. 应用效果与证据强度

### 7.1 历史独立 v2 评测

以下结果来自旧部署检查点在 490 条冻结人工候选上的历史测试，不是近期候选的新成绩。测试池包含广告富集采样，不能用类别比例推断自然浏览广告比例。

| 模式 | 广告精确率 | 广告召回率 | F1 | 确定判断覆盖率 | 分类 FPR | 页面动作 FPR | ECE | P95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 纯规则 | 96.43% | 36.49% | 0.5294 | 77.76% | 0.24% | 0.24% | 0.0675 | 0.036 ms |
| 纯模型 | 0% | 0% | 0 | 99.18% | 0.72% | 0% | 0.0907 | 109.878 ms |
| 普通级联 | 90.32% | 37.84% | 0.5333 | 98.78% | 0.72% | 0.24% | 0.0630 | 92.787 ms |
| JEV 协议 | 90.32% | 37.84% | 0.5333 | 98.78% | 0.72% | 0.24% | 0.0631 | 92.845 ms |

覆盖率表示得到确定判断的候选比例，不是网页覆盖率。FPR 为非广告被误判或误动作的比例；ECE 为置信度校准误差，越低通常表示概率与观测频率更接近。历史 P95 是离线候选决策测量，不能与浏览器整页延迟或后文真实请求耗时直接横比。

规则识别 27/74 条广告，级联识别 28/74，点估计多1条。按63个域名配对聚类bootstrap（10000次、种子42），召回差值95%区间为[0,4.71]个百分点，分类F1差值区间为[-0.0245,0.0463]；广告召回McNemar双侧精确检验p=1.0。结果与零增益不可区分，不能宣称统计显著。级联精确率下降，但没有增加页面动作误杀，说明策略层在该有限样本中约束了部分模型错误，并不意味着真实误杀风险为零。详细方法与限制见项目内`docs/historical-paired-statistics.md`。

普通级联与协议结果接近，尚未证明协议额外分支的独立增益。公开广告测试页曾用于调规则，相关高分只能作为兼容性回归，不能替代未知网站盲测。

### 7.2 当前能够支持的结论

- 工程上已实现多层广告判断、风险执行与数据闭环。
- 旧检查点不适合单独承担广告识别；该旧检查点的额外收益仍未获充分支持。
- 新候选已有新增冻结盲测，支持本批数据上的额外动作召回，但开发与盲测结果均不能直接外推到正式部署。
- SSA、v3 输入和轻量预筛选目前都不能作为已验证增益宣传。

本批证据支持候选级联额外召回，但不能据最高分自动部署：Qwen存在误杀，v3在种子42优于v2、种子7反而较差，仍无稳定输入升级证据。0/283误杀也不等于风险为零，候选独立Wilson上界约1.34%。耗时只包含预热后串行决策核心，不代表HTTP、浏览器或整页性能。

旧490条评测与新352条评测的样本和检查点不同，不计算跨表提升幅度。新模型无证据诊断均出现非零广告识别，但不能只归因于某一训练改动。当前部署未更新。完整指标、区间和时序披露见项目内`docs/fresh-blind-interpretation.md`及`artifacts/evaluation-fresh-blind-v1/`。

## 8. 性能优化与资源开销

### 8.1 已采用的控制手段

模型采用 NF4 四位双重量化、有限输入长度和微批处理；本机配置使用 384 token、微批量 2、4096 MiB CUDA 分配器预算。规则优先、请求内去重、有界 TTL 缓存、模型调用预算和延迟加载共同限制成本。

该预算不等于显卡总占用上限。历史本地测试峰值约为已分配 3836 MiB、保留 4084 MiB；驱动、上下文及其他进程仍会占显存。小样本 3 GiB 实验曾成功，但尚未证明长输入与持续负载下性能等价，未替换正式 4 GiB 配置。

### 8.2 真实浏览观测与异步冷启动

首次实际采样包含 26 个请求、209 个候选：171 个来自规则、20 个来自跨请求缓存、18 个提交模型，无模型错误或预算延后。模型状态占候选约 8.61%；该比例来自一次有限浏览，不能视为长期固定调用率。

原同步加载期间，请求中位数约 1.272 ms，P95 约 8.54 秒，模型批次存在更大长尾。该观测提示优先处理冷启动，而非盲目扩容缓存。

已实现后台单实例加载与有限预热，状态分为 idle、loading、warming、ready、failed。前台在未准备好时返回等待状态；扩展约 2 秒后有界重扫。等待不写语义缓存、不采集为训练标签，失败有退避。公开配置默认关闭该模式，本机配置已在用户更新扩展后启用。

异步加载减少前台等待阻塞，不减少权重加载或 GPU 计算本身；模型未就绪期间灰区广告可能暂时显示。现有小流量观察不足以宣布真实 P95 已稳定下降。

### 8.3 性能可观测性

`/v1/status` 提供请求、候选、热缓存、批内复用、模型预算、模型批次、异常和来源统计，耗时窗口最多保留 512 项。统计不保存域名、文本或 URL，服务重启清零。编排耗时不包含完整 HTTP 解密、探针推理与浏览器执行，并发时间不可直接相加推导 CPU 占用。

### 8.4 轻量影子路径的后续验证

已完成真实轻量输出的合成页面执行一致性检查，正文、导航、表单和视频控件保留；但模型对合成Sponsored卡片仅给出约0.502概率而放行，首轮期望识别的测试失败并保留。另用明确标注的固定输出验证隐藏、原display恢复和断线放行，后者只证明执行链路，不是模型识别成绩。

匿名真实页面影子轮访问6页，收到223个候选：212个明确候选跳过、8次重复跳过，实际判断3个灰区，建议放行2个、隐藏1个。没有发送任何轻量新增动作，无队列丢弃或模型异常。唯一潜在隐藏对象截图为空白，仍为未标注材料，不能当作确认广告或误杀。

Python进程在模型初始化后RSS约135.9MiB、运行峰值约142.8MiB，不含浏览器子进程；初始化约1.21秒。仅3次影子调用，P95约8.43ms，不能当成稳定性能。规则基线与影子轮访问成功数、候选数不同，不用两轮耗时差推导因果开销。

据此保留独立影子研究工具，不注册默认CPU执行后端，也不替换当前Qwen。队列64、去重512、延迟窗口512；过载和异常不改变主路径。当前回归192项通过（8.60秒）。详见项目内`docs/lightweight-shadow-validation.md`。

## 9. 隐私、安全与许可边界

候选仅保留有限短文本、选定属性、结构与脱敏资源线索，排除整页 HTML、Cookie、认证头、表单值及 URL 凭据等。SSA 进一步限制为结构变化统计，拒绝额外字段。

扩展与服务通过一次性配对建立临时会话，采用 P-256 ECDH、HKDF-SHA256、AES-256-GCM，结合时间窗口、序号与防重放验证。Base64 仅用于编码，不承担加密功能。该设计不能保护已经被恶意软件或本地管理员控制的机器，也不替代完整安全审计。

自有代码根许可证为 Apache-2.0；第三方规则、基础模型、数据和其他资产遵循各自许可。部分 tracker 资产含 CC BY-NC-SA 来源，不受根许可证统一覆盖。公开时需保留来源与通知，模型权重是否分发、分发何种文件需另行明确。

本项目的自有工程贡献主要是类型化决策协议、分类与执行边界、分歧复核、受预算约束的影子审计、版本化输入和可追溯评测闭环。Qwen、LoRA、NF4 与第三方过滤规则属于已有技术，不能作为新基础算法主张。
