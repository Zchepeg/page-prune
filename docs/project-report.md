# PagePrune（滤页）项目阶段报告

报告日期：2026年10月31日。依据当前代码、配置及已保存的独立评测，扩展版本为 0.10.1。

## 1. 项目定位

本项目是面向 Chromium 浏览器的本地决策感知广告屏蔽框架，结合网络规则、页面元素分析和 Qwen 专项决策器，兼顾拦截覆盖、页面完整性、隐私与运行成本。

目前已形成浏览器扩展、本地服务、数据复核、训练校准和独立评测的完整链路。已知广告主要由规则处理，模型用于灰区候选。项目不依赖官方 Jev 实现，当前属于可运行的研究原型；独立评测尚未证明模型具有显著的额外拦截收益。

## 2. 架构与实用技术

| 层次 | 技术与实现 | 作用 |
| --- | --- | --- |
| 浏览器执行 | Manifest V3、declarativeNetRequest、CSS、内容脚本 | 网络拦截、同步隐藏、动态候选发现及手动标记 |
| 候选处理 | DOM 结构、有限短文本、尺寸、可见性、资源主机与脱敏 | 将网页转换为有界决策输入 |
| 确定性判断 | 域名、资源路径和 DOM 规则 | 快速处理明确广告和明确非广告 |
| 专项模型 | Qwen3-4B-Base、LoRA、pointer head、PyTorch、Transformers | 对灰区元素输出广告与非广告概率 |
| 风险策略 | 置信阈值、校准档位、受保护元素、可恢复隐藏 | 将分类结论转换为允许执行的动作 |
| 数据闭环 | JSONL、来源记录、去重、人工复核、独立域名切分 | 支撑训练、审计与可复现评测 |
| 本地通信 | HTTP 回环服务、一次性配对、ECDH、HKDF、AES-GCM | 保护扩展与服务之间的双向数据交换 |

核心流程：候选发现 → 脱敏 → 规则判断 → 灰区模型决策 → 风险策略 → 页面动作；分歧及高价值未知样本进入人工复核。

静态网络层覆盖广告网络、分析脚本、社交像素和会话录制服务。域名表通过分块 requestDomains 规则压缩，避免逐域名生成规则造成数量膨胀；主文档导航排除在拦截范围之外，大规模 DNS 来源域名表限定为第三方请求，以降低页面损坏风险。

## 3. 核心算法与设计思想

### 3.1 规则优先的级联决策

高置信规则结果直接执行快速路径，只有灰区与配置允许的边界候选调用模型。这样将模型成本集中在需要上下文判断的部分，避免让概率模型重复学习明确的域名事实。

JEV-Ad 协议统一描述规则证据、语义概率、模型版本与不确定状态。边界挑战中若规则与模型冲突，结论降级为不确定并进入保守处理。当前配置关闭模型挑战规则阻断，待候选模型通过独立验证后再考虑启用。

### 3.2 选项指针决策器

模型输入由候选状态、任务说明和候选选项组成。主干提取决策位置与选项位置的表示，指针头通过投影后的相似度计算选项分数，再经温度校准得到概率。

选项隔离注意力使各选项只能读取公共状态和自身内容，决策位置读取全部选项；训练时打乱选项顺序，降低位置偏置。模型直接完成选项评分，无需生成长篇自然语言回答。

新模型训练采用广告、非广告二分类；低置信度、类别间隔不足或输入截断等情况由协议转为不确定，避免把“证据不足”混同为一种内容类别。

### 3.3 判断与执行分离

模型认为是广告，并不意味着页面一定执行阻断。策略层继续检查概率、校准档位和元素风险，对正文、导航、表单、输入框及按钮等结构实施保护。模型或服务异常时，依赖本地决策的路径默认放行；浏览器内置静态规则仍独立工作。

### 3.4 主动学习与影子审计

主动学习根据规则—模型分歧、不确定度及规则边界距离排列复核优先级。模型预测不会直接回灌为训练标签；强规则采集保留弱标签来源，人工确认样本单独记录。普通可见元素的随机对照采样用于减轻只采集疑似广告造成的选择偏差。

SSA 影子审计针对已放行但仍可疑的元素，以 0.1%～1% 分层采样，观察延迟状态、DOM 变化、可见性和已有资源关联。每标签页每小时最多 3 个、每域名每小时最多 20 个探针。探针只观察已加载页面，不产生额外广告请求；高信息结果进入复核，暂不直接改变页面或参与训练。其增益尚未获得独立评测支持。

## 4. 训练与性能优化

训练采用 LoRA、域名隔离验证、早停、最佳检查点恢复和温度校准。新增训练策略包括规则证据随机丢弃、部分表面特征丢弃、域名频次加权及标签平滑，目的在于减少规则捷径和高频网站记忆；这些策略的效果仍需新检查点实验验证。

运行时采用 NF4 四位双重量化、BF16 计算、384 token 上限及微批量 2。线程安全延迟加载使纯规则浏览期间无需加载模型；候选去重、有界 TTL 缓存、长度分桶和每请求模型数量上限共同控制开销。训练默认关闭，由用户单独运行，完成后不自动部署。

当前正式配置仍为 4096 MiB CUDA 分配器预算。近期在 20 条验证样本上的加载实验中，关闭 Transformers 分配器预热后，3072 MiB 预算能够运行，预测概率哈希与基线一致，已分配显存峰值约 2733 MiB、保留显存约 2884 MiB；2816 MiB 接近预算上限，2688 MiB 加载失败。

该实验说明存在降低缓存开销的空间，但样本量较小，延迟统计包含首次推理开销，不能据此保证所有输入下性能不变。3 GiB 方案尚未接入正式加载路径，也不等于整机或显卡总显存需求；发布前还需覆盖长输入、持续负载及驱动开销。

## 5. 应用效果与独立评测

当前主要证据来自冻结的独立人工盲标集：490 条候选、63 个域名，其中广告 74 条、非广告 416 条，与 401 个训练域名无重叠。该测试池包含广告富集采样，指标描述的是候选级表现，不能直接代表全网拦截率。

| 模式 | 广告精确率 | 广告召回率 | F1 | 页面动作误杀率 | P95 决策延迟 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 纯规则 | 96.43% | 36.49% | 0.5294 | 0.24% | 0.036 ms |
| 纯模型 | 0% | 0% | 0 | 0% | 109.878 ms |
| 规则—模型级联 | 90.32% | 37.84% | 0.5333 | 0.24% | 92.787 ms |
| JEV-Ad 协议 | 90.32% | 37.84% | 0.5333 | 0.24% | 92.845 ms |

级联相比纯规则多找回 1 条广告，召回率增加 1.35 个百分点，F1 增加约 0.39 个百分点，未增加页面动作误杀，但精确率下降，推理延迟增加。纯模型未识别出真实广告，并出现 3 条错误广告分类；这些分类未转化为页面误杀，体现了策略层的保护作用。

完整协议及加入 SSA 的模式尚未显示超过普通级联的检测收益。因此目前不能宣称模型可替代规则、显著提高准确率，或影子探针已经提高广告发现能力。

历史浏览器试运行中，用户曾反馈部分公开广告测试页满分。这说明对应规则和页面执行路径得到改善；由于部分公开探针已用于规则构建，其分数属于兼容性回归结果，不能充当未知网站泛化能力的独立证据。

## 6. 隐私、原创贡献与当前阶段

候选采用字段白名单和长度限制，排除整页 HTML、Cookie、凭据与表单值；探针进一步限制为结构变化统计。通信使用临时密钥及序号、时间窗口、防重放校验，Base64 仅承担编码。原始采集、人工标签、配对记录与模型权重不进入公开仓库。

项目自有设计集中在决策协议、风险执行边界、分歧驱动复核、低预算影子审计及训练评测治理的组合与实现。Qwen、LoRA、量化和第三方规则属于既有技术或上游资产，不能据此主张新的基础模型算法或量化算法。自有代码采用 Apache-2.0，第三方资产保留各自许可边界。

当前已具备本地广告屏蔽与研究迭代所需的工程闭环，主要瓶颈是灰区模型对未知域名的广告识别能力。后续应优先补充独立人工广告样本、验证新增训练策略，并以新增广告召回、页面误杀和延迟共同决定模型是否值得部署；显存优化则需完成正式加载路径与持续负载验证。
