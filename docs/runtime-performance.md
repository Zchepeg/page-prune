## 新增指标

`GET /v1/status`新增performance聚合字段：请求开始、完成、在途和失败数；候选数量、跨请求热缓存命中；批内模型候选重复、唯一模型需求、预算延后；模型批次、提交状态数、模型异常；来源与动作计数；请求、准备阶段和模型批次耗时。

耗时仅保留最近512条样本，计数为本进程累计。模型批次耗时每实际批次只记录一次，不把它重复计入每候选延迟后相加。热缓存命中只统计准备阶段已有的缓存，批内复用另计。缓存自身另提供原始查询命中、未命中、过期、淘汰和驻留数量；原始命中包括批内复用查询，不能当作跨请求命中率。驻留数量可能含尚未访问清理的过期项。

scope仅覆盖候选编排，不包括探针推理、HTTP解析/加密或浏览器执行。并发请求耗时可能重叠，不代表CPU占用时间。unique_model_demand为逐请求内去重后的需求累计，并非跨所有历史请求的全局唯一状态数。

所有聚合不存域名、文本、候选ID或URL。使用短临界区锁保护并发计数，延迟窗口有界；这些监测仍有少量开销，未声称免费。服务重启后指标归零。

## 采样方式

已保存初始聚合快照。保持扩展启用，正常浏览文章、信息流等页面并刷新或回访部分页面，再保存后续快照：

```powershell
python scripts/capture_performance_snapshot.py --out runs/performance-observation-v1/after.json
```

比较时先确认service.started_at相同；若服务重启，不能直接作累计差分。重点查看热缓存命中比例、模型状态/候选比例、批内重复、预算延后、模型异常与请求/模型P95。只有真实数据表明某条路径占主要成本，才调整缓存、跨批次合并或调用预算。
